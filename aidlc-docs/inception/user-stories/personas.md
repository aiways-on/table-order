# 페르소나 (Personas) — 테이블오더 서비스

**단계**: INCEPTION → User Stories (Part 2)
**분류 방식**: Persona 2종 (승인된 계획: Q1=A)

---

## Persona 1: 고객 (Customer) — "지민"

| 항목 | 내용 |
|------|------|
| **아키타입** | 매장에 착석해 테이블 태블릿으로 직접 주문하는 방문객 |
| **기술 숙련도** | 보통 — 스마트폰 앱 사용에 익숙, 별도 학습 없이 직관적으로 사용 |
| **접점** | 테이블에 고정된 태블릿(브라우저 웹 UI, 자동 로그인 상태) |
| **목표** | ① 대기·직원 호출 없이 즉시 원하는 메뉴 주문 ② 주문 접수/진행 상태를 스스로 확인 |
| **동기** | 빠르고 편한 주문, 내 주문이 제대로 접수됐다는 확신 |
| **특성** | 로그인/설치 없이 즉시 사용, 터치 조작, 다양한 연령층, 짧은 체류·빠른 판단 |
| **페인포인트** | 직원 호출 대기, 복잡한 조작, 주문 접수 여부 불확실, 이전 손님 주문이 섞여 보이는 혼란 |
| **성공 기준** | 3~4번의 터치로 주문 완료, 주문번호 확인, 현재 세션 내역만 명확히 표시 |

## Persona 2: 매장 관리자/운영자 (Store Admin) — "현우"

| 항목 | 내용 |
|------|------|
| **아키타입** | 매장을 설정·운영하고 실시간 주문을 관리하는 운영자(사장/매니저) |
| **기술 숙련도** | 보통~높음 — 관리 도구 사용에 익숙, 효율 중시 |
| **접점** | 관리자용 웹 UI (매장 식별자 기반 인증, 16시간 세션) |
| **목표** | ① 들어오는 주문을 놓치지 않고 실시간 처리 ② 테이블·메뉴·세션을 효율적으로 관리해 인건비 절감 |
| **동기** | 운영 효율, 실시간 현황 파악, 오류(중복/오주문) 신속 정정 |
| **특성** | 다수 테이블을 한 화면(그리드)에서 모니터링, 피크 시간대 빠른 상태 변경 필요, 멀티매장 중 자기 매장만 관리 |
| **페인포인트** | 신규 주문 인지 지연, 테이블별 현황 파악 어려움, 세션 종료·직권 수정 등 반복 처리의 번거로움 |
| **성공 기준** | 신규 주문 2초 내 인지, 클릭 몇 번으로 상태 변경/세션 종료, 과거 내역 손쉬운 조회 |

## 페르소나-스토리 매핑 요약
- **고객(지민)**: EPIC-AUTH(고객측), EPIC-MENU(조회), EPIC-ORDER(장바구니/주문/내역)
- **관리자(현우)**: EPIC-AUTH(관리자측), EPIC-MENU(관리), EPIC-ORDER(모니터링), EPIC-SESSION(테이블/세션/이력), EPIC-TENANT(격리)

상세 매핑은 `stories.md`의 각 스토리 **Persona** 필드 참조.
