## 3. 기능 요구사항 (Functional Requirements)

### 3.1 고객용 (Customer)

- **FR-C1 테이블 태블릿 자동 로그인 및 세션 관리**
  - 관리자가 1회 초기 설정: 매장 식별자 / 테이블 번호 / 테이블 비밀번호 입력 → 로그인 정보 로컬 저장
  - 1회 로그인 성공 후 저장된 정보로 자동 로그인
- **FR-C2 메뉴 조회 및 탐색**
  - 메뉴 화면이 기본 화면으로 항상 표시
  - 카테고리별 분류/이동, 메뉴 상세(메뉴명·가격·설명·이미지 URL)
  - UI: 카드 레이아웃, 터치 친화 버튼(최소 44x44px), 명확한 시각적 계층
- **FR-C3 장바구니 관리**
  - 메뉴 추가/삭제, 수량 증감, 총액 실시간 계산, 비우기
  - 클라이언트 로컬 저장(새로고침 시 유지), 서버 전송은 주문 확정 시에만
- **FR-C4 주문 생성**
  - 최종 확인 → 확정 → 주문번호 표시 → 장바구니 자동 비우기 → 메뉴 화면 자동 리다이렉트
  - 실패 시 에러 표시 및 장바구니 유지
  - 주문 정보: 매장 식별, 테이블 식별, 메뉴 목록(메뉴명·수량·단가), 총액, 세션 ID
- **FR-C5 주문 내역 조회**
  - 주문 시간순 정렬, 주문별 상세(주문번호·시각·메뉴/수량·금액·상태[대기중/준비중/완료])
  - **현재 테이블 세션 주문만** 표시(이전 세션·이용완료 주문 제외), 페이지네이션/무한스크롤
  - **실시간 상태 업데이트 포함(SSE)** — Q8=A 결정 반영

### 3.2 관리자용 (Admin)

- **FR-A1 매장 인증**
  - 매장 식별자 + 사용자명 + 비밀번호 로그인
  - JWT 기반, 16시간 세션 유지(새로고침 시 유지), 16시간 후 자동 로그아웃
  - 비밀번호 bcrypt 해싱, 로그인 시도 제한
- **FR-A2 실시간 주문 모니터링**
  - **SSE 기반** 주문 목록 실시간 업데이트(2초 이내 표시)
  - 그리드/대시보드 레이아웃: 테이블별 카드, 총 주문액, 최신 주문 n개 미리보기
  - 주문 카드 클릭 시 전체 메뉴 상세, 상태 변경(대기중/준비중/완료), 신규 주문 시각 강조, 테이블별 필터링
- **FR-A3 테이블 관리**
  - 테이블 태블릿 초기 설정(번호/비밀번호, 16시간 세션 생성, 자동 로그인 활성화)
  - 주문 삭제(직권 수정): 확인 팝업 → 즉시 삭제 → 총액 재계산 → 피드백
  - 테이블 세션 처리: 세션 시작(첫 주문)/종료(이용 완료) 관리, 종료 시 주문 내역을 과거 이력으로 이동 + 현재 주문/총액 0 리셋, 새 고객 시작 가능
  - 과거 주문 내역 조회: 테이블별 시간 역순, 주문번호·시각·메뉴·총액·이용완료 시각, 날짜 필터
  - 데이터: OrderHistory 테이블 저장, 세션 ID로 그룹화, 완료 시각 기록
- **FR-A4 메뉴 관리**
  - 카테고리별 조회, 등록(메뉴명·가격·설명·카테고리·이미지 URL), 수정, 삭제, 노출 순서 조정
  - 필수 필드 검증, 가격 범위 검증

### 3.3 멀티테넌시 (신규 결정 반영)
- **FR-MT1**: 모든 데이터(매장/메뉴/주문/이력/세션)는 매장 식별자로 격리되어야 함
- **FR-MT2**: 관리자·고객의 모든 요청은 자신의 매장 범위 데이터에만 접근 가능(테넌트 격리 — SECURITY-08 IDOR 방지와 연계)

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능
- **NFR-P1**: 관리자 실시간 주문 모니터링에서 신규 주문이 **2초 이내** 표시(SSE)
- **NFR-P2**: 소규모(데모/MVP) 트래픽 기준 응답성 확보

### 4.2 보안 (Security Baseline 적용 — SECURITY-01~15)
- **NFR-S1 (SECURITY-12)**: 관리자 비밀번호 bcrypt 해싱, 로그인 브루트포스 방지(잠금/지연), JWT 서버측 검증(만료·서명), 세션 쿠키 Secure/HttpOnly/SameSite, 하드코딩 크리덴셜 금지
- **NFR-S2 (SECURITY-05)**: 모든 API 파라미터 입력 검증(타입·길이·형식), 파라미터라이즈드 쿼리(SQL 인젝션 방지), XSS 방지
- **NFR-S3 (SECURITY-08)**: 기본 인증 필수(공개 엔드포인트 명시), 객체 수준 인가(테넌트/테이블 소유권 검증, IDOR 방지), 관리자 권한 서버측 검증, CORS 화이트리스트
- **NFR-S4 (SECURITY-04)**: HTML 제공 엔드포인트에 보안 헤더(CSP, HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy)
- **NFR-S5 (SECURITY-01)**: 데이터 저장소 저장시 암호화 + 전송중 암호화(TLS) — 로컬/데모 환경에서는 구성 가능 범위 내 적용, N/A 항목은 근거와 함께 표기
- **NFR-S6 (SECURITY-03/14)**: 구조적 로깅(타임스탬프·상관ID·레벨), 민감정보 로깅 금지, 인증 실패 등 보안 이벤트 알림
- **NFR-S7 (SECURITY-10)**: 의존성 잠금 파일, 취약점 스캔, 신뢰 소스만 사용, Docker 이미지 태그 고정
- **NFR-S8 (SECURITY-15)**: 모든 외부 호출 오류 처리, fail-closed, 전역 에러 핸들러, 사용자 대상 일반 에러 메시지

### 4.3 복원력 (Resiliency Baseline 적용 — RESILIENCY-01~15)
- **NFR-R1 (RESILIENCY-01)**: 컴포넌트별 비즈니스 크리티컬리티 분류 및 의존성 매핑
- **NFR-R2 (RESILIENCY-02)**: RTO/RPO = 시간 단위, DR 전략 = **Backup & Restore**
- **NFR-R3 (RESILIENCY-06)**: 각 서비스 헬스 체크 엔드포인트, 크리티컬 서비스는 다운스트림(DB) 연결 확인 딥 헬스체크
- **NFR-R4 (RESILIENCY-10)**: 모든 외부 호출(DB 등) 명시적 타임아웃, 비크리티컬 의존성 실패 시 그레이스풀 디그레이드 정의
- **NFR-R5 (RESILIENCY-12)**: 영속 데이터 자동 백업 구성, 백업 암호화, 보존 정책 정의, 복원 검증 절차 문서화
- **NFR-R6 (RESILIENCY-05)**: 메트릭·로그·(다중 서비스 시)트레이스 관측성, 운영 대시보드 정의
- **RESILIENCY-04/08/14**: NFR Design 단계에서 결정 예정

### 4.4 테스트 (Property-Based Testing 적용 — PBT-01~10)
- **NFR-T1 (PBT-09)**: PBT 프레임워크 선정 및 의존성 포함 — Python은 **Hypothesis** 권장
- **NFR-T2 (PBT-01)**: Functional Design에서 컴포넌트별 테스트 가능 속성 식별(라운드트립·불변식·멱등성·상태 기반 등)
- **NFR-T3 (PBT-02/03/04)**: 직렬화 라운드트립, 비즈니스 불변식(예: 총액 = Σ(단가×수량), 할인 없음, 세션 종료 후 현재 총액=0), 멱등성(예: 세션 종료 재적용) 속성 테스트
- **NFR-T4 (PBT-06)**: 상태 기반 컴포넌트(장바구니, 테이블 세션/주문 파이프라인) 상태 기반 PBT
- **NFR-T5 (PBT-10)**: 예제 기반 테스트와 병행(비즈니스 크리티컬 경로는 두 방식 모두)

### 4.5 유지보수성/품질
- **NFR-Q1**: 보안 크리티컬 로직(인증/인가) 전용 모듈 분리(SECURITY-11)
- **NFR-Q2**: 컨테이너화(docker-compose)로 로컬 재현 가능한 개발/실행 환경

## 5. 제약 사항 (Constraints) — `constraints.md` 반영 (구현 제외)

- **결제**: 실제 결제/PG 연동/영수증/환불/포인트·쿠폰 **제외**
- **인증/보안**: OAuth·SNS 로그인, 2FA/OTP **제외** (단, 관리자 JWT/bcrypt 기본 인증은 포함)
- **파일/컨텐츠**: 이미지 리사이징/최적화, CMS, 광고 **제외** (이미지는 URL 참조만)
- **알림**: 푸시/SMS/이메일/소리·진동 **제외**
- **주방**: 주방 전달, 식재료 재고 **제외**
- **고급 기능**: 분석·대시보드(매출), 매출 리포트, 재고 관리, 직원/권한 관리, 예약, 리뷰, 다국어 **제외**
- **외부 연동**: 배달 플랫폼, POS, SNS 공유, 지도/번역 API **제외**

> **주의**: 확장(보안/복원력/관측성)이 요구하는 로깅·모니터링은 위 "분석/리포트 제외"와 상충하지 않음 — 전자는 운영 관측성, 후자는 비즈니스 분석 기능임.

## 6. MVP 범위 (요구사항 §4 기준)

**고객용**: 자동 로그인/세션, 메뉴 조회, 장바구니, 주문 생성(주문번호 표시 후 자동 리다이렉트), 현재 세션 주문 내역 조회(실시간)
**관리자용**: 매장 인증(16h 세션), 실시간 주문 모니터링(그리드+SSE), 테이블 관리(초기 설정/주문 삭제/이용 완료/과거 내역), 메뉴 관리

## 7. 핵심 데이터 개체 (초안 — Application/Functional Design에서 구체화)

- **Store**(매장): 매장 식별자, 이름, 관리자 계정(username, bcrypt password_hash)
- **Menu**(메뉴): store_id, 메뉴명, 가격, 설명, 카테고리, 이미지 URL, 노출 순서
- **Table**(테이블): store_id, 테이블 번호, 테이블 비밀번호(해시), 자동 로그인 설정
- **TableSession**(테이블 세션): store_id, table_id, 시작 시각, 종료(이용완료) 시각, 상태
- **Order**(주문): store_id, table_id, session_id, 주문번호, 시각, 항목(메뉴명·단가·수량), 총액, 상태(대기중/준비중/완료)
- **OrderHistory**(주문 이력): 세션 종료 시 이동, session_id 그룹화, 이용완료 시각

## 8. 핵심 요구사항 요약 (Key Requirements Summary)

- 멀티테넌트 테이블오더 (고객 웹 UI + 관리자 웹 UI + FastAPI 백엔드 + 관계형 DB), 로컬 docker-compose 실행
- 실시간성: 관리자 모니터링 및 고객 주문상태 모두 **SSE**
- 세션 중심 모델: 테이블 세션 라이프사이클(시작→주문→이용완료→이력 이동/리셋)이 도메인의 핵심
- 보안: 관리자 JWT/bcrypt, 테넌트/테이블 격리(IDOR 방지), 입력검증, 보안 헤더
- 결제/알림/주방/분석/외부연동은 범위 외
- 확장 3종(보안·PBT·복원력) 전면 적용 — 각 후속 단계 완료 시 컴플라이언스 요약 필수
